Данное руководство описывает стиль написания научных текстов, статей и диссертационных работ, основанный на анализе реальных работ автора.

## 0. ПРИНЦИПЫ ПРИМЕНЕНИЯ ПАТТЕРНОВ

### 🔴 КРИТИЧЕСКИ ВАЖНО: Контекстный анализ перед применением паттернов

**Паттерны НЕ применяются случайным образом!** 

Перед применением любого паттерна необходимо проанализировать:

#### 1. Позиция в тексте
- **Начало статьи/раздела?** → Требуется контекстуализирующая вводная фраза ("В настоящее время...", "В последние годы...")
- **Середина раздела?** → Проверить связь с предыдущим абзацем
- **Конец раздела?** → Может потребоваться завершающая связка

#### 2. Связь с предыдущим абзацем
- **Продолжение той же темы?** → Использовать связующие вводные конструкции ("В связи с этим,", "В такой ситуации...")
- **Новая подтема?** → Использовать переходные конструкции ("Так,", "Однако,")
- **Переход от проблемы к решению?** → Требуется предложение-мост ("В данной статье предлагается решение данной проблемы.")

#### 3. Логическая структура предложений
- **Два предложения связаны логически?** → Рассмотреть объединение через союз "а" или тире
- **Второе предложение поясняет первое?** → Использовать тире вместо точки
- **Мысль искусственно разорвана?** → Объединить в одно предложение

#### 4. Разнообразие вводных конструкций
- **Уже использовали "Так," в соседних абзацах?** → Заменить на "Например,", "Однако,", "При этом,"
- **Монотонность начала абзацев?** → Варьировать вводные конструкции

#### 5. Структура повествования
**Правильная последовательность в абзаце:**
1. Связь с предыдущей мыслью (если нужна)
2. Напоминание контекста/проблемы (если читатель мог забыть)
3. Новая информация/решение
4. Детализация (если нужна)

**Пример правильной структуры:**
```markdown
В данном исследовании, для решения поставленной задачи, используется аналогичный подход - 
для агрегации данных, необходимых для проактивного управления обновлением образовательных программ ИКТ-направлений, 
разработана формальная модель на основе теории Демпстера–Шафера.
```
↑ Связь с предыдущим → Напоминание цели → Решение

## 1. Структура текста

### 1.1. Абзацы

**КЛЮЧЕВОЕ ПРАВИЛО:** Каждая логическая мысль начинается с нового абзаца.

#### Принципы:
- Не создавать длинные абзацы (максимум 5-7 предложений)
- Каждый абзац = одна законченная мысль
- Короткие абзацы улучшают читаемость

#### Примеры из текстов:

✅ **Правильно:**
```
Однако у этого ответа есть несколько недостатков:

1. Одна и та же компетенция может быть закрыта в том или ином разрезе несколькими дисциплинами.
```

❌ **Неправильно:**
```
Однако у этого ответа есть несколько недостатков: одна и та же компетенция может быть закрыта в том или ином разрезе несколькими дисциплинами, компетенции, указываемые работодателями в вакансиях, практически всегда написаны неформальным языком...
```

### 1.2. Начало абзацев

Характерные вводные слова для связи между абзацами:

| Вводное слово | Назначение | Новый абзац? | Пример |
|---------------|------------|--------------|--------|
| **Так,** | Конкретизация | **✅ ВСЕГДА!** | "Так, формальные процедуры пересмотра РПД оказываются инерционными" |
| **Так, например,** | Конкретный пример | **✅ ВСЕГДА!** | "Так, например, взрывной рост спроса фиксируется в зонах, связанных с ИИ" |
| **В таких условиях** | Вывод после примера | **✅ Да** | "В таких условиях проактивная коррекция программ должна опираться..." |
| **Также** | Дополнение информации | Иногда | "Также стоит учитывать, что люди не любят использовать большое количество разных сервисов" |
| **Однако** | Контраст, возражение | **✅ Часто** | "Однако у этого ответа есть несколько недостатков" |
| **Таким образом,** | Заключение | Да | "Таким образом, путём составления User Stories Map определён функционал системы" |
| **Для этого** / **Для решения** | Описание цели/решения | Да | "Для решения этой проблемы необходим проактивный подход" |
| **В качестве...** | Детализация | Может остаться в том же | "В качестве таких источников предлагается рассматривать..." |

**🔴 КРИТИЧЕСКИ ВАЖНО:** 

**"Так," для конкретизации или примера ВСЕГДА начинает НОВЫЙ абзац!**

✅ **Правильно:**
```markdown
Особенно заметно это в отрасли ИКТ, где стремительное развитие технологий приводит к расхождению [2].

Так, формальные процедуры пересмотра рабочих программ дисциплин (РПД) и учебных планов оказываются инерционными.
```

❌ **Неправильно:**
```markdown
Особенно заметно это в отрасли ИКТ, где стремительное развитие технологий приводит к расхождению [2]. Так, формальные процедуры пересмотра рабочих программ дисциплин (РПД) и учебных планов оказываются инерционными.
```

**Общий принцип:** Каждое предложение с вводным словом, которое вводит новую подмысль или детализацию, становится отдельным абзацем.

#### 🔴 КРИТИЧНО: Разнообразие вводных конструкций

**ЗАЧЕМ:** Избегать монотонности и повторов. Если несколько абзацев подряд начинаются с "Так,", текст становится однообразным и теряет динамику.

**КОГДА использовать "Так,":**
- Первый пример или конкретизация после общего утверждения
- Переход к новой подтеме
- **НЕ ИСПОЛЬЗОВАТЬ:** если предыдущий абзац уже начинался с "Так,"

**КОГДА использовать "Так, например," вместо "Так,":**
- Когда приводите КОНКРЕТНЫЙ пример (с числами, датами, конкретными случаями)
- Усиливает акцент на том, что это именно пример, иллюстрация

**Пример проблемы - монотонность:**
❌ 
```markdown
Так, формальные процедуры пересмотра РПД оказываются инерционными.

Так, в технической диагностике DST используется для объединения показаний датчиков.

Так, в управлении человеческими ресурсами создаются системы оценки компетенций.
```
↑ Три абзаца подряд с "Так," - монотонно!

✅ **С разнообразием:**
```markdown
Так, формальные процедуры пересмотра РПД оказываются инерционными.

Для решения подобных задач, как показывает опыт, успешно применяется теория Демпстера–Шафера. Например, в технической диагностике DST используется для объединения показаний датчиков.

В управлении человеческими ресурсами на основе DST создаются системы оценки компетенций.
```
↑ Варьирование вводных конструкций

**Алгоритм выбора вводной конструкции:**
1. Проверить, как начинался предыдущий абзац
2. Если был "Так," → использовать "Например,", "Однако,", "При этом,", "В частности,"
3. Если приводите пример с конкретными данными → "Так, например," или просто "Например,"
4. Если переход к следствию → "В связи с этим,", "В такой ситуации"

### 1.3. Баланс абзацев

**ПРАВИЛО БАЛАНСА:**

Абзацы не должны быть:
- ❌ Слишком короткими (1 предложение без детализации)
- ❌ Слишком длинными (более 5-7 предложений)
- ✅ **Оптимально: 2-4 предложения на одну логическую мысль**

#### Когда объединять абзацы

Если второе предложение **детализирует** первое (отвечает на "какие?", "как?", "что именно?"), они остаются в одном абзаце.

✅ **Правильно (объединено):**
```markdown
Для решения этой проблемы необходим проактивный подход, основанный на интеграции разнородных источников информации. В качестве таких источников предлагается рассматривать данные о вакансиях и трендах рынка, нормативные основания (ФГОС/РПД), экспертные оценки работодателей, а также прогнозы востребованности навыков на горизонте 2–3 лет, т.к. они позволяют составить объективную картину состояния рынка труда.
```
↑ Одна мысль: какой подход нужен + какие источники использовать

❌ **Неправильно (слишком дробно):**
```markdown
Для решения этой проблемы необходим проактивный подход.

В качестве таких источников следует рассматривать данные о вакансиях...
```
↑ Первое предложение слишком короткое, а второе его детализирует

#### Когда разделять абзацы

Если предложение вводит **новую подмысль** (не детализирует предыдущую), оно начинает новый абзац.

✅ **Правильно (разделено):**
```markdown
...а также прогнозы востребованности навыков на горизонте 2–3 лет.

Так, например, взрывной рост спроса фиксируется в зонах, связанных с ИИ.

В таких условиях проактивная коррекция программ должна опираться на агрегирование разнотипных сигналов.
```
↑ Три разные мысли: источники → пример → вывод

### 1.4. Усиление аргументации

#### Причинно-следственные связи

Использовать **"т.к." (так как)** для добавления обоснований:

```markdown
...а также прогнозы востребованности навыков на горизонте 2–3 лет, т.к. они позволяют составить объективную картину состояния рынка труда.
```

**Другие варианты:**
- "поскольку" - для причины
- "в связи с" - для контекста

**Эффект:** Делает утверждения более убедительными и доказательными.

---

#### Усиление доказательности через вводные конструкции

**ЗАЧЕМ:** Добавление ссылок на опыт/практику усиливает убедительность утверждения, показывая, что это не теоретическое предположение, а проверенный подход.

**КОГДА применять:**
- При описании метода, который вы предлагаете использовать
- При утверждении об эффективности какого-то подхода
- Когда нужно обосновать выбор конкретного решения

**КОГДА НЕ применять:**
- При описании своих оригинальных результатов (там нужны ссылки на эксперименты)
- Слишком часто в тексте (не каждое предложение нуждается в такой вставке)

**Проблема без усиления:**
❌ 
```markdown
Для решения подобных задач агрегации разнородных данных в условиях неопределённости успешно применяется теория Демпстера–Шафера.
```
↑ Утверждение висит в воздухе. Почему мы это знаем? На основании чего?

✅ **С усилением:**
```markdown
Для решения подобных задач агрегации разнородных данных в условиях неопределённости, как показывает опыт, успешно применяется теория Демпстера–Шафера.
```
↑ Явная отсылка к проверенности подхода, академичнее

**Типовые конструкции:**
- ", как показывает опыт," - для общепринятых подходов
- ", как свидетельствует практика," - для практического применения
- ", согласно исследованиям," - для научно подтверждённых фактов
- ", как показали эксперименты," - для экспериментально проверенных утверждений

**Размещение:** Всегда в СЕРЕДИНЕ предложения (в запятых), не в начале и не в конце.

#### Уточнение формулировок

**ЗАЧЕМ:** Правильный выбор слов делает текст точнее, академичнее и естественнее. Некоторые конструкции звучат более формально, другие - более естественно для русского языка.

**Предпочтительные формулировки:**

| Менее точно | Более точно | Пояснение | КОГДА менять |
|-------------|-------------|----------|---------------|
| "следует рассматривать" | "предлагается рассматривать" | мягче | При описании своих предложений |
| "с рынка и из образовательной среды" | "с рынка труда" | конкретнее | Когда говорим именно о рынке труда |
| "прогнозы спроса" | "прогнозы спроса на конкретные навыки" | точнее | Когда нужна конкретизация |
| "программ и учебных планов" | "рабочих программ и учебных планов" | полнее | Всегда (РПД - принятый термин) |
| "остаётся критичной" | "является весьма критичной" | усиление | В начале статьи, для подчёркивания актуальности |
| "разнотипных" | "разнородных" | академичнее | Всегда |
| "столь" | "настолько" | естественнее | Всегда ("столь" устаревшее) |
| "конфликтующих" | "противоречивых" | точнее для данных | При описании данных/источников |
| "В настоящем исследовании" | "В данном исследовании" | нейтральнее | Всегда |
| "объединения" | "проведения качественного анализа" | конкретнее | Когда речь о методе, а не просто о сборе |

### 1.5. Языковая чистота

**🔴 КРИТИЧЕСКИ ВАЖНО: Избегать англицизмов**

#### Недопустимые конструкции

**1. Использование "vs." для перечисления**

❌ **Неправильно:**
```markdown
рынок вакансий vs. ФГОС/РПД vs. экспертные оценки
источник1 vs. источник2 vs. источник3
```

✅ **Правильно:**
```markdown
рынок вакансий, ФГОС/РПД, экспертные оценки и т.п.
источник1, источник2, источник3 и т.п.
```

**Правило:** Перечисление через запятую с завершающим "и т.п."

---

**2. Английские расшифровки в скобках**

❌ **Неправильно:**
```markdown
доказательная (evidence-based) основа
проактивный (proactive) подход
```

✅ **Правильно:**
```markdown
доказательная основа
проактивный подход
```

**Исключение:** Технические аббревиатуры и термины первого упоминания:
- ✅ Теория свидетельств Демпстера–Шафера (DST)
- ✅ Рабочая программа дисциплины (РПД)
- ✅ ФГОС ВО (федеральный государственный образовательный стандарт высшего образования)

### 1.6. Многоуровневая структура абзацев

**Принцип: Общее → Конкретика → Вывод**

Даже короткий абзац можно и нужно разделить по логическим уровням мышления.

#### Уровень 1: Общая мысль

Описание концепции, теории, подхода в общем виде.

```markdown
Для агрегации разнородных источников информации предлагается использовать теорию свидетельств Демпстера–Шафера (DST). Данная теория позволяет распределять «доверие» между подмножествами гипотез, формально учитывать неполноту и конфликт в источниках.
```

#### Уровень 2: Конкретное применение (часто с "Так,")

Как именно это работает в конкретном контексте.

```markdown
Так, применение DST позволяет учитывать конфликт между множеством анализируемых источников данных, таких, как рынок вакансий, ФГОС/РПД, экспертные оценки и т.п., а также поможет формировать управленческие решения по обновлению образовательных программ.
```

#### Уровень 3: Преимущество или вывод

Результат применения, преимущества, итоговый эффект.

```markdown
Таким образом, формируется доказательная основа для управленческих действий в вузе — от корректировки содержания рабочих программ дисциплин до назначения практик и формирования элективных курсов.
```

#### Полная структура из одной мысли

**Пример разбиения:**

1. **Общее:** Что такое DST
2. **Конкретика с "Так,":** Какие источники учитывает
3. **Преимущество "В отличие от...":** Почему лучше традиционных методов
4. **Вывод "Таким образом,":** Что получаем в результате

**Результат:** 4 абзаца вместо 1 длинного!

**Важно:**
- Количество абзацев **НЕ ограничено**
- Главное: разделять логические уровни
- Структура может быть глубже: Общее → Конкретика 1 → Конкретика 2 → Преимущество → Вывод

### 1.7. Связность текста

**🔴 КРИТИЧЕСКИ ВАЖНО: Текст не должен быть набором разрозненных фактов!**

Каждый абзац должен логически связываться с предыдущим и следующим.

#### Контекстуализирующие вводные фразы

**ЗАЧЕМ:** Вводные фразы устанавливают контекст и создают плавный переход между абзацами. Они предотвращают "зависание в воздухе" утверждений без временной или логической привязки.

**КОГДА применять:**

**1. Временной контекст ("В настоящее время...", "В последние годы...")**

**КОГДА:** 
- Самое начало статьи/раздела (особенно первый абзац)
- Введение новой проблемы
- Описание текущего состояния дел

**ЗАЧЕМ:** Начинать абзац со слова "Проблема..." некорректно - нужна временная привязка. Вводная фраза добавляет актуальность и контекст.

**Пример проблемы:**
❌ "Проблема несоответствия подготовки выпускников остаётся критичной..."
↑ Начало без контекста, утверждение "висит в воздухе"

✅ "В настоящее время проблема несоответствия подготовки выпускников актуальным запросам работодателей является весьма критичной..."
↑ Установлен временной контекст, подчёркнута актуальность

---

**2. Причинно-следственный контекст ("В связи с этим,", "В такой ситуации...")**

**КОГДА:** 
- Переход от описания проблемы к её следствиям
- Переход к выводу после описания ситуации
- Связь нового абзаца с предыдущим

**ЗАЧЕМ:** Следующий абзац ОБЯЗАТЕЛЬНО должен быть связан с предыдущим. Без связки текст превращается в набор разрозненных утверждений.

**Пример проблемы:**
❌ Абзац 1: "...образовательные программы устаревают быстрее..."
   Абзац 2: "Традиционные подходы демонстрируют низкую эффективность..."
↑ Нет связи между абзацами

✅ Абзац 1: "...образовательные программы устаревают быстрее..."
   Абзац 2: "В связи с этим, традиционные подходы к актуализации рабочих программ дисциплин демонстрируют низкую эффективность..."
↑ Явная причинно-следственная связь

**Выбор конструкции:**
- "В связи с этим," - прямое следствие из предыдущего
- "В такой ситуации..." - вывод/реакция на описанную ситуацию
- "В этих условиях..." - переход к описанию решения

---

**3. Контекст исследования ("В данной статье...", "В данном исследовании...")**

**КОГДА:**
- Переход от общего обзора к описанию своего исследования
- После описания проблемы - введение своего решения
- Когда читатель мог забыть начальную проблему

**ЗАЧЕМ:** Явная ссылка на текущую работу помогает читателю понять, что сейчас описывается именно предлагаемое решение, а не общий обзор.

**Пример проблемы:**
❌ "Разработана формальная модель на основе теории Демпстера–Шафера..."
↑ Непонятно: это чужая работа из обзора или ваше решение?

✅ "В данном исследовании, для решения поставленной задачи, используется аналогичный подход - для агрегации данных... разработана формальная модель..."
↑ Ясно, что это ваше решение; есть связь с предыдущей темой

**Предпочтения:**
- "В данном исследовании" > "В настоящем исследовании" (нейтральнее)
- "В данной статье" - для более неформального стиля

#### Связь между абзацами

**1. Вводные предложения-мосты**

Целое предложение для плавного перехода от одной темы к другой.

✅ **Правильно:**
```markdown
...методы диагностики и разрешение конфликтов в объединённых данных.

И такие исследования уже проводились, например, в близком к данной работе, прикладному исследованию в области HR-аналитики для распределения персонала...
```

**Предложения-мосты между проблемой и решением**

**ЗАЧЕМ:** Явное связующее предложение предотвращает резкий скачок от описания проблемы к техническим деталям решения. Читатель должен понять, что начинается описание ВАШЕГО решения, а не продолжается обзор чужих работ.

**КОГДА применять:**
- После завершения описания проблемы, перед описанием своего решения
- После обзора существующих подходов, перед описанием своего подхода
- Когда нужно явно обозначить переход от "что не так" к "что мы предлагаем"

**Проблема без моста:**
❌ 
```markdown
...классические статистические методы не обеспечивают надёжного объединения данных.

Для решения подобных задач агрегации разнотипных данных успешно применяется теория Демпстера–Шафера.
```
↑ Непонятно: это продолжение описания проблемы? Обзор существующих методов? Или УЖЕ ваше решение?

✅ **С мостом:**
```markdown
...классические статистические методы не обеспечивают возможности проведения качественного анализа настолько разнородных и противоречивых источников информации. В данной статье предлагается решение данной проблемы.

Так, для решения подобных задач агрегации разнородных данных, как показывает опыт, успешно применяется теория...
```
↑ Ясная граница: проблема → ПРЕДЛАГАЕМОЕ решение

**Типовые формулировки мостов:**
- "В данной статье предлагается решение данной проблемы." (самый явный)
- "Настоящее исследование направлено на устранение этого разрыва."
- "Для преодоления указанных ограничений предлагается..."
- "В данном исследовании используется аналогичный подход -" (при наличии связи с предыдущими примерами)

**2. Завершающие связки**

Последнее предложение абзаца готовит читателя к следующей теме.

✅ **Правильно:**
```markdown
...может быть применим в академическом контексте взаимодействия «вуз–предприятие», но существуют и более продвинутые методы применения DST.

Так, дальнейшее развитие логики «оценка компетенций → решение о назначении» получило отражение...
```

**3. Разнообразие вводных слов**

❌ **НЕ злоупотреблять одним словом!**

Особенно опасно: многократное использование "Так," в начале абзацев.

✅ **Правильно — чередовать:**

| Вводное слово | Когда использовать | Пример |
|---------------|-------------------|--------|
| **Так,** | Конкретизация после общего | "Так, теоретическую основу заложили..." |
| **Однако,** | Контраст, смена фокуса | "Однако, при построении систем..." |
| **Например,** | Конкретный пример | "Например, метрики близости..." |
| **И такие...** | Связь с предыдущей мыслью | "И такие исследования уже проводились..." |
| **При этом,** | Дополнительная информация | "При этом особое значение имеют..." |
| **В частности,** | Конкретизация | "В частности, расстояние Жуссельма..." |

#### Связь внутри абзаца

**1. Использование относительных местоимений**

Вместо прямого перечисления — более плавная конструкция.

❌ **Неправильно:**
```markdown
методы, устойчивые к конфликтам между источниками
```

✅ **Правильно:**
```markdown
методы, которые устойчивы к конфликтам между источниками
```

**2. Уточнения в начале предложений**

Добавляют контекст и связь с предыдущим предложением.

Примеры:
- "В этом исследовании,"
- "В этой статье"
- "В ней" (вместо повтора)
- "При построении"
- "Для решения"

✅ **Правильно:**
```markdown
...предложена методика оценки кадров на основе DST. В этом исследовании, экспертные оценки...
```

**3. Избегание повторов**

❌ **Неправильно:**
```markdown
В этой работе предложена методика... В этой работе показано... В этой работе также...
```

✅ **Правильно:**
```markdown
В этой работе предложена методика... В ней показано... Также авторы...
```

#### Пример связного обзора литературы

```markdown
Для обоснования применимости DST необходимо рассмотреть теоретическую базу метода.

Так, теоретическую основу заложили работы А. Демпстера [3] и Г. Шафера [4]. В работе Шафера были введены функции масс, меры убеждённости и правдоподобия. Эти фундаментальные труды стали основой для развития прикладных методов, таких как диагностика и разрешение конфликтов.

Однако, при построении систем особое значение приобретают методы, которые устойчивы к конфликтам [6]. Например, метрики близости «тел свидетельств» количественно оценивают расхождения между базовыми вероятностными назначениями.

И такие исследования уже проводились, например, в области HR-аналитики [7]. В этой работе предложена многошаговая методика оценки кадров на основе DST. Данный подход может быть применим в академическом контексте, но существуют и более продвинутые методы.

Так, дальнейшее развитие получило отражение в моделях назначения волонтёров [8]. В этом исследовании, авторы объединили оценки способностей кандидатов...
```

**Обратите внимание:**
- Вводный абзац объясняет структуру
- "Так," → "Однако," → "И такие..." → "Так," — разнообразие
- Каждый абзац связан с предыдущим
- Внутри абзацев: "В работе", "В этой работе", "В этом исследовании"
- Завершающие связки готовят к следующей теме

### 1.8. Объединение и структурирование предложений

**🔴 КРИТИЧНО: Искусственно разорванные предложения режут слух!**

Длинное, но логичное предложение **ЛУЧШЕ** нескольких искусственно разделённых.

#### Объединение через запятую и союзы

**ЗАЧЕМ:** Предотвращает искусственный разрыв логически связанных утверждений. Когда второе предложение является полным продолжением мысли первого, точка между ними режет естественное течение текста.

**КОГДА применять:**
- Два предложения описывают **одну проблему** с разных сторон
- Второе предложение **продолжает** мысль первого, не завершённую полностью
- Оба утверждения логически параллельны (например, оба негативные или оба позитивные)

**КОГДА НЕ применять:**
- Второе предложение вводит **новую мысль** (даже если связанную)
- Предложения слишком длинные (итоговое > 3 строк)
- Логика отношений сложнее, чем простое продолжение

**Проблема искусственного разрыва:**
❌ 
```markdown
Проблема несоответствия остаётся критичной для высшего образования. Стремительное развитие технологий приводит к тому, что образовательные программы устаревают быстрее...
```
↑ Первое предложение неожиданно обрывается. Второе буквально продолжает описание той же проблемы - почему она критична. Точка здесь искусственна.

✅ **Объединение через союз "а":**
```markdown
В настоящее время проблема несоответствия подготовки выпускников актуальным запросам работодателей является весьма критичной для высшего образования, а стремительное развитие технологий в сфере ИКТ приводит к тому, что образовательные программы устаревают быстрее...
```
↑ Естественное течение: проблема критична + КОНКРЕТИЗАЦИЯ почему (развитие технологий)

**Выбор союза:**
- **"а"** - для логически параллельных утверждений, часто с оттенком контраста или дополнения
- **"и"** - для простого добавления
- **", при этом"** - для уточнения деталей

---

#### Объединение через тире

**ЗАЧЕМ:** Тире сигнализирует, что второе предложение ПОЯСНЯЕТ или КОНКРЕТИЗИРУЕТ первое. Это предотвращает искусственный разрыв между тезисом и его обоснованием.

**КОГДА применять:**
- Второе предложение отвечает на вопрос "Почему?" или "В чём именно?" к первому
- Второе предложение раскрывает механизм/детали, упомянутые в первом
- Между предложениями отношение "УТВЕРЖДЕНИЕ - КОНКРЕТИЗАЦИЯ"

**КОГДА НЕ применять:**
- Второе предложение вводит новый аспект, а не поясняет предыдущий
- Между предложениями отношение "И ЕЩЁ" вместо "А ИМЕННО"

**Проблема искусственного разрыва:**
❌ 
```markdown
Традиционные подходы демонстрируют низкую эффективность. Формальный пересмотр программ происходит с задержкой в 1-2 года...
```
↑ Мысль буквально разорвана. Читатель после первого предложения думает: "В чём именно низкая эффективность?" - и тут же получает ответ во втором предложении. Это ОДНА мысль!

✅ **Объединение через тире:**
```markdown
Традиционные подходы к актуализации рабочих программ дисциплин демонстрируют низкую эффективность - формальный пересмотр программ происходит с задержкой в 1-2 года, при этом доступная информация о требованиях рынка труда остаётся фрагментарной и противоречивой.
```
↑ ТЕЗИС - ПОЯСНЕНИЕ: первое утверждение + конкретизация, в чём именно проблема

**Различие тире vs. союз "а":**
- **Тире** - для ПОЯСНЕНИЯ (второе раскрывает первое)
- **"а"** - для ДОПОЛНЕНИЯ (два параллельных утверждения)

#### Когда НЕ нужно разрывать предложения

**1. Описание исследования + что в нём предложено**

❌ **Неправильно (искусственный разрыв):**
```markdown
И такие исследования уже проводились, например, в близком к данной работе, прикладному исследованию в области HR-аналитики для распределения персонала с учётом компетенций [7]. В ней предложена многошаговая методика оценки кадров на основе DST...
```

✅ **Правильно (естественное течение):**
```markdown
И такие исследования уже проводились, например, в близком к данной работе, прикладному исследованию в области HR-аналитики для распределения персонала с учётом компетенций [7] была предложена многошаговая методика оценки кадров на основе DST...
```

**Объяснение:**
- Убираем точку после [7]
- Убираем "В ней"
- Объединяем через глагол "была предложена"
- Предложение длинное, но естественное

---

**2. Ссылка на модель + что в ней сделано**

❌ **Неправильно (разорванное):**
```markdown
Так, дальнейшее развитие логики «оценка компетенций → решение о назначении» получило отражение в моделях назначения спасателей и волонтёров [8]. В этом исследовании, с помощью DST и языковых термов авторы объединили оценки способностей кандидатов...
```

✅ **Правильно (слитное через относительное местоимение):**
```markdown
Так, дальнейшее развитие логики «оценка компетенций → решение о назначении» получило отражение в моделях назначения спасателей и волонтёров [8], в котором, с помощью DST и языковых термов авторы объединили оценки способностей кандидатов...
```

**Объяснение:**
- Заменяем точку на запятую
- "В этом исследовании," → ", в котором,"
- Предложение становится длинным, но связным

---

#### Когда разрыв ОПРАВДАН

**Общее утверждение → Детализация**

✅ **Правильно разделить:**
```markdown
Так, теоретическую основу теории доказательств Демпстера–Шафера (DST) заложили работы А. Демпстера по верхним и нижним вероятностям [3] и монография Г. Шафера «A Mathematical Theory of Evidence» [4].

В работе Шафера были введены функции масс, меры убеждённости и правдоподобия, а также правило комбинирования свидетельств для согласования информации из противоречивых источников.
```

**Объяснение:**
- Первое предложение: КАКИЕ работы заложили основу
- Второе предложение (новый абзац): ЧТО ИМЕННО было введено в работе Шафера
- Разрыв оправдан — переход от общего к детализации

---

#### Сравнение подходов

| Ситуация | Неправильно | Правильно |
|----------|-------------|-----------|
| Исследование + результат | "...исследование [7]. В ней..." | "...исследование [7] была предложена..." |
| Модель + описание | "...в моделях [8]. В этом исследовании,..." | "...в моделях [8], в котором,..." |
| Общее → Детали | Объединять в одно длинное | Разделить на 2 абзаца |

---

#### Принципы

1. **Длинное предложение ЛУЧШЕ искусственного разрыва**
   - Если предложение логически связано — не разрывать!

2. **Объединение через глаголы**
   - "исследование [7] была предложена методика..."

3. **Объединение через относительные местоимения**
   - ", в котором," вместо "В этом исследовании,"
   - ", где" для уточнения места действия

4. **Разрыв только для новой логической мысли**
   - Общее утверждение → НОВЫЙ АБЗАЦ → Конкретизация

---

#### Примеры из реального текста

**До (с искусственными разрывами):**
```markdown
Теоретическую основу DST заложили работы А. Демпстера [3] и монография Г. Шафера [4]. В работе Шафера были введены функции масс. Эти труды стали базой.

Особое значение имеют методы, устойчивые к конфликтам [6]. Метрики близости «тел свидетельств» и расстояние Жуссельма оценивают расхождения. Данные инструменты позволяют управлять весами.
```

**После (с естественными длинными предложениями):**
```markdown
Так, теоретическую основу заложили работы А. Демпстера [3] и монография Г. Шафера [4].

В работе Шафера были введены функции масс, меры убеждённости и правдоподобия, а также правило комбинирования свидетельств для согласования информации из противоречивых источников.

Однако, при построении устойчивых систем информационного слияния особое значение приобретают методы, которые устойчивы к конфликтам между источниками [6]. Например, метрики близости «тел свидетельств» и расстояние Жуссельма количественно оценивают расхождения между базовыми вероятностными назначениями (BPA), позволяя эффективно управлять весами источников и выбирать оптимальные правила агрегации при высоком уровне конфликта.
```

**Результат:**
- Текст течёт естественно
- Длинные предложения не режут слух
- Связь между мыслями очевидна

| подъем | подъём |
| ученый | учёный |

**Прилагательные:**

| Неправильно | Правильно |
|-------------|-----------|
| четкий | чёткий |
| надежность | надёжность |

**Наречия и местоимения:**

| Неправильно | Правильно | Примечание |
|-------------|-----------|------------|
| еще | ещё | наречие |
| ее | её | притяжательное местоимение |

---

#### Важные случаи

**0. 🔴 КРИТИЧНО: "всё" vs "все" — зависит от контекста!**

Это **разные слова**, и выбор буквы зависит от значения:

**"всё" (через Ё) — средний род, единственное число**

Означает "всё целиком", "это всё", "всё это"

✅ **Правильно:**
```markdown
всё вышеперечисленное
всё это
всё множество
учитывать всё
несмотря на всё
```

**Проверка:** Можно заменить на "это"
- "всё это важно" = "это важно" ✓

---

**"все" (через Е) — множественное число**

Означает "все люди", "все элементы", "каждый"

✅ **Правильно:**
```markdown
все, кто принял участие
все участники
все исследования
все источники
для всех студентов
```

**Проверка:** Можно заменить на "каждый" или подразумеваются люди/предметы
- "все студенты" = "каждый студент" ✓

---

**Сравнение:**

| Контекст | Неправильно | Правильно | Объяснение |
|----------|-------------|-----------|------------|
| "это всё" | все вышеперечисленное | всё вышеперечисленное | можно заменить на "это" |
| люди/предметы | всё участники | все участники | множественное число |
| целиком | учитывать все | учитывать всё | означает "всё целиком" |
| каждый | всё источники | все источники | можно заменить на "каждый" |

**Примеры из научных текстов:**

✅ **Правильно:**
```markdown
Всё вышеперечисленное показывает необходимость разработки модели.
При этом все участники эксперимента подтвердили гипотезу.
Модель учитывает всё множество факторов.
Все источники данных были проверены на достоверность.
```

❌ **Неправильно:**
```markdown
Все вышеперечисленное показывает... (нужно "Всё" через Ё)
Всё участники эксперимента... (нужно "все" через Е)
```

---

**1. "её" vs "ее":**

❌ **Неправильно:**
```markdown
В ее основе лежит...
оценки ее качества
```

✅ **Правильно:**
```markdown
В её основе лежит...
оценки её качества
```

---

**2. "учёт" vs "учет":**

❌ **Неправильно:**
```markdown
с учетом данных
в работе учет...
```

✅ **Правильно:**
```markdown
с учётом данных
в работе учёт...
```

Но: "учитывает", "учитывается" (глаголы без "ё")

---

**3. "даёт" vs "дает":**

❌ **Неправильно:**
```markdown
что дает возможность
модель дает результат
```

✅ **Правильно:**
```markdown
что даёт возможность
модель даёт результат
```

---

#### Примеры из научных текстов

```markdown
Модель даёт возможность учитывать её особенности с учётом неполноты данных.
```

## 3. Структура документа

### 3.1. Связывающий текст между заголовками

**🔴 ОБЯЗАТЕЛЬНОЕ ПРАВИЛО: Между заголовками ВСЕГДА должен быть текст!**

Особенно критично между **разноуровневыми заголовками** (заголовок раздела → подраздел).

---

#### Зачем нужен связывающий текст

1. **Подводит от общего к частному**
   - От раздела к подразделу

2. **Объясняет структуру**
   - Какие подразделы будут рассмотрены
   - В какой последовательности

3. **Создаёт логический переход**
   - Плавное введение в тему
   - Мотивация для изучения подразделов

---

#### Формат

```markdown
## Заголовок раздела

[Вводный текст: что будет рассмотрено, структура, логика изложения]

### Первый подраздел

[Содержание подраздела]

### Второй подраздел

[Содержание подраздела]
```

**Что включить во вводный текст:**
- Краткое описание содержания раздела
- Перечисление основных подразделов
- Логическая последовательность изложения
- Связь с предыдущими разделами (если нужно)

---

#### Примеры

**❌ Неправильно (нет связывающего текста):**

```markdown
## Модель принятия решений на основе теории Демпстера–Шафера

### Базовые распределения масс источников (BPA)

В рамках теории свидетельств каждому источнику...
```

**Проблема:** Прыжок с заголовка раздела сразу на подраздел без объяснения структуры.

---

**✅ Правильно (метод "по цепочке"):**

```markdown
## Модель принятия решений на основе теории Демпстера–Шафера

Для решения задачи интеграции разнородных источников данных о компетенциях 
необходимо определить базовые распределения масс для каждого источника информации.

### Базовые распределения масс источников (BPA)

В рамках теории свидетельств каждому источнику...

[Содержание подраздела]

После формирования базовых распределений необходимо учесть различия в 
качестве источников.

### Дисконтирование источников

[Содержание подраздела]

Далее необходимо объединить информацию из различных источников.

### Комбинирование свидетельств
```

**Преимущества:**
- Подводка только к первому подразделу (НЕ перечисляются все сразу!)
- Каждый подраздел плавно переходит в следующий
- Текст читается как единое повествование
- Метод "по цепочке"

---

#### Типовые вводные фразы

**Для структурирования раздела:**
- "Рассмотрим последовательно ключевые компоненты..."
- "Для решения задачи необходимо..."
- "Модель включает следующие этапы..."
- "Далее представлено описание основных элементов..."
- "В данном разделе детализируется..."

**Для перечисления подразделов:**
- "Так, в первую очередь необходимо..."
- "После этого выполняется..."
- "Затем рассматривается..."
- "Далее на основе... формируются..."

**Для связи с предыдущими разделами:**
- "Опираясь на представленную выше постановку..."
- "В данном разделе детализируется описанная ранее модель..."
- "Для реализации поставленных задач необходимо..."

---

#### Длина связывающего текста

| Оценка | Количество | Пример |
|--------|------------|---------|
| **Оптимально ✅** | 1-3 абзаца (2-6 предложений) | См. примеры выше |
| **Слишком коротко ❌** | 1 предложение | "Рассмотрим компоненты модели." |
| **Слишком длинно ❌** | Целая страница | Это уже отдельный подраздел! |

---

#### Сравнение: До и После

**До (без связывающего текста):**

## 6. Структура документа

### 6.1. Типичные разделы

1. **Введение** - постановка проблемы, актуальность
2. **Основная часть** - описание методов, анализ, результаты
3. **Вывод** - обобщение результатов, заключение

### 6.2. Введение

Содержит:
- Постановку проблемы
- Актуальность исследования
- Цель работы
- Задачи исследования

#### Пример:

```
Составление рабочих программ дисциплин в вузе процесс достаточно трудоёмкий. Это создаёт трудности при составлении рабочей программы дисциплины. Целью данной работы является формирование математической модели для сопоставления данных вакансий с компетенциями в РПД.
```

### 6.3. Вывод

Характерные конструкции:

```
В результате...
```

```
Таким образом...
```

```
По итогу получается...
```

**Особенности:**
- Использование прошедшего времени для описания выполненной работы
- Допустимо использование "мы"
- Краткое перечисление результатов

#### Примеры из текстов:

```
В результате анализа процесса формирования рабочей программы дисциплины преподавателем, была разработана математическая модель, позволяющая рассчитывать каждый шаг преподавателя.
```

## 7. Чего следует избегать

❌ **Не использовать:**

1. **Разговорные выражения**
   - Плохо: "куча проблем"
   - Хорошо: "ряд проблем", "множество трудностей"

2. **Личные местоимения в основном тексте**
   - Плохо: "Я разработал модель"
   - Хорошо: "Была разработана модель"
   - Исключение: "мы" допустимо в выводах

3. **Эмоциональные оценки**
   - Плохо: "отличный результат"
   - Хорошо: "положительный результат"

4. **Длинные абзацы без структуры**
   - Делить на короткие абзацы
   - Использовать списки

5. **Неформальный язык**
   - Соблюдать академический тон
   - Использовать профессиональную терминологию

## 8. Библиографические ссылки и цитирование

### 8.1. Формат ссылок

**В тексте:**
- Используются квадратные скобки: [1], [2]
- Несколько источников: [1, 2, 3]
- Размещение: **после** утверждения, **до** точки

#### Примеры:

✅ **Правильно:**
```
согласно ФГОС [1].
```

```
согласно исследованию [15], более половины опрошенных педагогов тратят на подготовку материалов более двух часов в день.
```

❌ **Неправильно:**
```
согласно ФГОС. [1]
```

### 8.2. Список литературы

**Название раздела:**
- "Список информационных источников"
- "Список использованной литературы"

**Формат записи:**
1. Номер. Автор(ы). Название // Издание. – Год. – Том, № выпуск. – Страницы.
2. Для электронных ресурсов: URL: адрес (дата обращения: дд.мм.гггг).

#### Примеры из текстов:

```
1. Приказ Министерства образования и науки РФ от 19 сентября 2017 г. N 918 "Об утверждении федерального государственного образовательного стандарта высшего образования" URL: https://fgosvo.ru/uploadfiles/... (дата обращения: 15.10.2023).
```

### 8.3. Аннотации и ключевые слова

**Аннотации:**
- Обязательны на **русском и английском** языках
- Размещаются в начале работы
- Формат: __Аннотация__ или __Annotation__

**КЛЮЧЕВЫЕ ПРАВИЛА ДЛЯ АННОТАЦИЙ:**

⛔ **НЕДОПУСТИМО:**
- Использовать нумерованные или маркированные списки
- Разбивать на много абзацев
- Использовать "В работе" (только "В статье")
- Использовать "математические выкладки" (правильно: "математический аппарат")

✅ **ОБЯЗАТЕЛЬНО:**
- Компактная структура: 2-3 предложения
- Перечисление через запятые в скобках: (элемент1, элемент2, а также элемент3)
- Использовать "а также" для связи последнего элемента
- Причастия активной формы: "основанная на" (не "на основе")
- Прямые формулировки: "учитывает" (не "при неполноте")
- "В статье приведены" для перечисления содержания

**Ключевые слова:**
- Следуют после аннотации
- Формат: __Ключевые слова:__ *слово1, слово2, слово3*
- Текст ключевых слов в курсиве

#### Пример ПРАВИЛЬНОЙ аннотации:

```markdown
__Аннотация__

В статье предлагается формальная модель, основанная на теории свидетельств Демпстера–Шафера (DST), для проактивного управления развитием инженерно-технических компетенций в вузе. Модель агрегирует разнородные источники (вакансии, ФГОС/РПД, экспертные оценки, а также прогнозы спроса), учитывает неполноту и конфликт данных, и возвращает управляемые метрики (Bel, Pl, BetP, конфликт K), которые используются как триггеры обновления рабочих программ дисциплин (РПД) и индивидуальных учебных планов (ИУП). В статье приведены математический аппарат, алгоритм агрегации свидетельств и протокол экспериментальной проверки эффекта модели.

__Ключевые слова__

*Теория Демпстера–Шафера, управление компетенциями, рабочие программы дисциплин (РПД).*
```

#### Пример НЕПРАВИЛЬНОЙ аннотации:

```markdown
❌ НЕПРАВИЛЬНО:

__Аннотация__

В работе рассматривается применение теории на основе DST.

Предложена модель. В качестве источников используются:

1. вакансии
2. РПД
3. эксперты

Также в работе приведены математические выкладки.

Проблемы:
- Используется список
- Много абзацев
- "В работе" вместо "В статье"
- "на основе" вместо "основанная на"
- "математические выкладки" вместо "математический аппарат"
- "Также" в начале предложения
```

## 11. Примеры применения правил

### Пример 1: Правильная структура

```markdown
Однако у этого ответа есть несколько недостатков:

1. Одна и та же компетенция может быть закрыта в том или ином разрезе несколькими дисциплинами.
2. Компетенции, указываемые работодателями в вакансиях, практически всегда написаны неформальным языком.
3. Анализ материалов нескольких РПД возможно только вручную и занимает достаточно много времени.

Также стоит учитывать, что люди не любят использовать большое количество разных сервисов.

Решением данной проблемы может стать автоматизированная система, предоставляющая преподавателям удобный интерфейс актуализации РПД, а абитуриентам и работодателям – простую и понятную информацию о компетенциях, получаемых выпускниками выбранного направления.
```
