# Нормализация BetP для распределения ресурсов учебной программы

Расширение алгоритма DST Level 0: введение Шага 5b, преобразующего пигнистические вероятности в корректное распределение бюджета фиксированного объёма.

---

## 1. Проблема: несовместимость шкал

После Шага 5 (см. `ALGORITHM_CURRENT.md`) каждый домен *D_i* получает значение:

```
BetP(D_i) = m*(T_i) + m*(U_i) / N
```

Это **независимая** вероятность DS-теории: «насколько рынок уверен, что домен D_i нужен специалисту». Поскольку одна вакансия может одновременно требовать несколько доменов, значения BetP **не конкурируют** между собой:

```
BetP(GENERAL)   = 0.72
BetP(BACKEND)   = 0.71
BetP(FRONTEND)  = 0.69
BetP(LANGUAGES) = 0.69
...
──────────────────────
Σ BetP ≈ 6.93   ← «рынок требует 693%» — это корректно!
```

Показатель покрытия учебной программы устроен иначе:

```
supply(D_i) = hours(D_i) / totalHours
```

Это **доля ресурсов**: домены конкурируют за фиксированный бюджет, поэтому:

```
Σ supply(D_i) ≤ 1.0
```

### Следствие: Δ_abs = BetP − supply сравнивает несопоставимые шкалы

| Метрика | Природа | Сумма по всем доменам |
|---|---|---|
| `BetP_i` | Абсолютная вероятность (независимая для каждого домена) | ~693% |
| `supply_i` | Относительная доля ресурсов (конкурирующие доли) | ≤ 100% |
| `Δ_abs = BetP − supply` | Корректна для **диагностики дефицита** | ~593% |

`Δ_abs` правильно отвечает на вопрос «есть ли разрыв между рыночным спросом и покрытием?» — это её законная роль. Однако она **не пригодна** для расчёта рекомендуемого числа часов, поскольку:

```
recHours = BetP_i × totalHours → Σ recHours = 6.93 × 648 = 4490 ч.  ≠  648 ч.
```

Рекомендации будут систематически избыточными и не могут быть выполнены в рамках фиксированного учебного плана.

---

## 2. Модификация алгоритма: Шаг 5b — нормализация BetP

### Формула

Приведём BetP к шкале, суммирующейся в 1.0 (аналогично `supply`):

```
nBetP(D_i) = BetP(D_i) / Σ_j BetP(D_j)
```

**Свойства:**
- `nBetP(D_i) ∈ (0, 1)` для каждого домена
- `Σ_i nBetP(D_i) = 1.0` — корректное распределение вероятностей
- Порядок доменов по `nBetP` совпадает с порядком по `BetP` — ранжирование не изменяется
- Домены с более высоким `BetP` получают больший `nBetP`-вес

### Рекомендуемые часы

```
recHours(D_i) = nBetP(D_i) × totalHours
```

**Свойство:** `Σ_i recHours(D_i) = totalHours` — сумма равна объёму учебного плана ✓

### Нормализованный показатель дефицита

```
Δ_norm(D_i) = nBetP(D_i) − supply(D_i)
```

Теперь обе шкалы суммируются в 1.0, и вычитание корректно:
- `Δ_norm > 0` → домен получает **меньше** часов, чем его пропорциональная доля рыночного спроса
- `Δ_norm < 0` → домен получает **больше** часов, чем его пропорциональная доля
- `Δ_norm ≈ 0` → покрытие соответствует рыночному весу домена

## 3. Влияние на Шаг 6: принятие решения

### Исходная логика (Шаг 6, `Δ_abs`)

```
Если Δ_abs > τ_Δ (0.15) → дефицит → «Усилить»
Если Δ_abs < −τ_Δ        → избыток → «Сократить»
```

Вопрос: **«есть ли рыночный дефицит у данного домена?»**  
Ответ корректен, но не учитывает бюджетное ограничение.

### Новая логика (Шаг 5b + Шаг 6, `Δ_norm`)

```
Если Δ_norm > τ_alloc → недо-представлен в бюджете → «Усилить»
Если Δ_norm < −τ_alloc → пере-представлен в бюджете → «Сократить»
```

Вопрос: **«правильно ли распределён бюджет учебного плана с учётом рыночных приоритетов?»**

### Семантическое различие

| Аспект | `Δ_abs` | `Δ_norm` |
|---|---|---|
| Вопрос | «Есть ли рыночный дефицит?» | «Оптимален ли бюджет?» |
| Операнды | BetP (абс.) vs supply (отн.) | nBetP (отн.) vs supply (отн.) |
| Сумма рекомендаций | >> totalHours | = totalHours ✓ |
| Применение | Диагностика | Перераспределение часов |

Оба показателя сохраняют свою роль: `Δ_abs` используется как исходный DST-сигнал («чего хочет рынок»), `Δ_norm` — как аллокационная рекомендация («как перераспределить ресурсы»).

## 4. Пример с реальными данными

Учебный план «Информационные системы и технологии», 648 ч., профессии: backend 70% + frontend 30%.

### До нормализации (`Δ_abs`)

| Домен | BetP | supply | Δ_abs | recHours* | Решение |
|---|---|---|---|---|---|
| GENERAL | 0.72 | 0.16 | +0.56 | 467 ч. | Срочно усилить |
| LANGUAGES | 0.69 | 0.27 | +0.42 | 447 ч. | Усилить |
| FRONTEND | 0.69 | 0.00 | +0.69 | 447 ч. | Срочно усилить |

`*recHours = BetP × 648`. Σ = 4490 ч. >> 648 ч. — нереализуемо.

### После нормализации (`Δ_norm`, Шаг 5b)

Σ BetP = 6.93

| Домен | BetP | nBetP | supply | Δ_norm | recHours | Решение |
|---|---|---|---|---|---|---|
| GENERAL | 0.72 | 0.104 | 0.164 | **−0.060** | 67 ч. | 🟢 Сократить |
| LANGUAGES | 0.69 | 0.099 | 0.269 | **−0.170** | 65 ч. | 🟢 Сократить |
| FRONTEND | 0.69 | 0.099 | 0.000 | **+0.099** | 65 ч. | 🔴 Усилить |
| DEVOPS | 0.68 | 0.098 | 0.000 | **+0.098** | 64 ч. | 🔴 Усилить |

Σ recHours = **648 ч. ✓**

**Интерпретация:** LANGUAGES и GENERAL получают сигнал «Сократить» — не потому что рынок их не ценит (BetP высокий), а потому что в учебном плане им выделена *непропорционально большая* доля бюджета. Освободившиеся ресурсы перераспределяются в пользу совершенно неохваченных доменов (FRONTEND, DEVOPS).

## 5. Связь с теорией Демпстера-Шафера

### BetP как пигнистическая вероятность (Smets, 1994)

`BetP` введена Смэтсом в рамках Transferable Belief Model (TBM) как **правило принятия решений** при заданной функции масс. Формально:

```
BetP({T}) = Σ_{A ⊇ {T}} m(A) / |A|
```

Для нашего двуэлементного пространства {T, F} с неопределённостью Θ = {T, F, ..., T_N}:

```
BetP(T) = m(T) + m(Θ) / N
```

где N — мощность пространства гипотез. В нашей реализации N = N_CLUSTERS = 25.

### Нормализация — операция вне DS-теории

Пигнистическая вероятность `BetP(D_i)` вычисляется **для каждого домена отдельно** в своём собственном пространстве гипотез {«нужен», «не нужен»}. DS-теория не предполагает нормировки значений BetP по множеству доменов — это операция **вне формализма DS**.

Нормализация `nBetP_i = BetP_i / Σ BetP_j` — это **постобработка**, преобразующая набор независимых вероятностных суждений в распределение ресурсов. По своей природе она аналогична:

- Softmax-преобразованию в нейросетях (нормировка логитов в распределение)
- Конверсии полезностных оценок в вероятностные веса (теория полезности)

### Ограничение метода

Нормализация по сумме BetP предполагает, что все рассматриваемые домены образуют **полное покрытие** профессиональной области. Если набор доменов неполный (например, отсутствуют домены с высоким BetP), нормированные веса будут искажены. Рекомендуется включать в анализ все домены, релевантные для целевых профессий (Level 0 → Level 1 детализация).

## 6. Итог: модифицированный алгоритм

```
Шаг 5 (существующий):
  BetP(D_i) = m*(T_i) + m*(U_i) / N
  Δ_abs(D_i) = BetP(D_i) − supply(D_i)     ← для диагностики дефицита

Шаг 5b (новый):
  nBetP(D_i) = BetP(D_i) / Σ_j BetP(D_j)  ← нормализация на множестве доменов
  recHours(D_i) = nBetP(D_i) × totalHours  ← Σ recHours = totalHours ✓
  Δ_norm(D_i) = nBetP(D_i) − supply(D_i)  ← для аллокационной рекомендации

Шаг 6 (расширенный):
  Аллокационная рекомендация: на основе Δ_norm
  DST-диагностика (абс. дефицит): на основе Δ_abs  ← сохраняется как отдельный сигнал
```
