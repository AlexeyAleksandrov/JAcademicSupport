# DST Yager Rule — анализ конфликта и кандидатов

## 1. Источники и инструмент

- Python-скрипт: `skill-atomize-test/yager_candidates.py`
- Java-логика: `src/main/java/.../services/dst/DstCombinationService.java`
- Порог: `src/main/java/.../services/dst/DstSettingsDefaults.java` (`TAU_K = 0.40`)
- БД: PostgreSQL `AcademicSupport`

Запуск:

```powershell
# в папке skill-atomize-test
python yager_candidates.py
```

Скрипт считает BPA для источников VAC/EXP/FC, их дисконтирование и комбинацию по правилу Демпстера/Ягера.

## 2. Условие перехода на Ягер

В `DstCombinationService.combineAdaptive`:

```text
K = m1(T) · m2(F) + m1(F) · m2(T)
K >= tauK() ? combineYager() : combineDST()
tauK = 0.40
```

Ягер перекладывает конфликт `K` в `m(U)`, поэтому в финальном `decide(...)` при высоком `K` выдаётся рекомендация `expertise` (высокая неопределённость).

## 4. Формула негативной массы FC

```text
mF(FC raw) = (1 - exp(-lambda · n / t)) · avg_conf
mF(FC discounted) = mF(FC raw) · W_FC
```

где:

- `lambda = 2` (`LAMBDA_FC_L2`)
- `W_FC = 0.6`
- `n` — число негативных источников по навыку
- `t` — общее число источников прогнозов (`COUNT(DISTINCT source_url)` = 23)

## 5. Сколько негативных прогнозов докинуть

При `mT(VAC) ≈ 0.8` и `tauK = 0.4` нужно:

```text
mF(FC discounted) · mT(VAC) >= 0.4
mF(FC discounted) >= 0.5
mF(FC raw) >= 0.5 / 0.6 ≈ 0.83
```

При `avg_conf = 0.9` это требует `n / t ≈ 0.9`, то есть почти все источники по навыку должны быть негативными.

### Моделирование для PHP

Добавляем новые **уникальные** негативные источники с `avg_conf = 0.9` (общее число источников `t` растёт).

| +new neg | total | neg | mF(FC discounted) | max K | Yager? |
|----------|-------|-----|-------------------|-------|--------|
| 0 | 23 | 5 | 0.1544 | 0.124 | нет |
| +20 | 43 | 25 | 0.3572 | 0.242 | нет |
| +50 | 73 | 55 | 0.4131 | 0.280 | нет |
| +100 | 123 | 105 | 0.4381 | 0.296 | нет |
| +500 | 523 | 505 | 0.4608 | 0.312 | нет |

При `avg_conf = 0.9` Ягер не срабатывает даже при 505 негативных источниках из 523.  
**Чтобы Ягер сработал, нужно** `avg_conf ≈ 1.0` и `n / t` близко к `1.0` (фактически все источники по навыку — негативные). Тогда `K ≈ 0.415`.

## 6. Выводы

1. **Ягер с текущими параметрами почти недостижим.** Нужна одновременно сильная позитивная вакансионная масса и подавляющее негативное прогнозное большинство.
2. **PHP на текущих данных далёк от Ягера**: `K ≈ 0.12`.
3. **Ближайшие кандидаты** — `Ruby` и `Objective-C` (`K ≈ 0.18`), но и им нужны десятки/сотни новых уверенных негативных источников.
4. Если всё-таки «докинуть» десятки негативных прогнозов, результат будет не `reduce`, а `expertise` (высокая неопределённость). Это и есть «свести к неопределённости».
5. Если нужна **ясная негативная рекомендация**, не надо гнаться за `K >= 0.4`. Нужен навык с низким `mT(VAC)`/EXP и умеренным `mF(FC)` — тогда Демпстер без Ягера даст `reduce`.
